- **Perceval `Parameter` arithmetic (e.g. `theta_param + np.pi/4`) breaks MerLin's trainable-parameter name-mapping** — the resulting derived expression-Parameter's auto-generated name (e.g. `"(theta0 + 0.785...)"`) isn't found in MerLin's `param_mapping`, raising `KeyError` deep in `merlin.pcvl_pytorch.locirc_to_tensor`. Fix: use two separate `PS` gates in sequence on the same mode (one bare trainable `pcvl.Parameter`, one fixed non-parameterized constant) — phase shifters on the same mode compose additively, so this is physically identical, not an approximation.
- **MerLin's default `ComputationSpace.UNBUNCHED` silently drops real probability mass for any circuit where genuine photon bunching is physically possible** (e.g. `heralded_cz`/`PostProcessedControlledRotationsItem`'s internal Hong-Ou-Mandel-type interference) — confirmed live: gave a herald-failure probability of ~0.194 instead of the correct ~0.9259 (Phase 10's independently-established 2/27 heralded_cz success rate) until `measurement_strategy=ML.MeasurementStrategy.probs(computation_space=ML.ComputationSpace.FOCK)` was passed explicitly to `QuantumLayer(...)`. Weight-1 circuits happen to be safe under the UNBUNCHED default (bunching is structurally impossible there — verified, not assumed), but any weight-2/ancilla-bearing circuit needs `FOCK` explicitly.
- **`MerLin.QuantumLayer` construction cost is dominated by a large one-time cost that scales with circuit/Fock-space size, not by per-draw evaluation cost** — measured directly at n=8 weight-1: ~40s to construct, then ~0.2s per subsequent forward+backward pass on the same layer (reused across draws, only parameter values change). Timing a layer over only a handful of draws and extrapolating linearly to 100 draws overestimates total cost by an order of magnitude or more (confirmed live: an initial 3-draw timing estimate implied ~3.5-4h for a sweep that actually completed in ~10.5 minutes) — always isolate construction time from marginal per-draw time before estimating sweep duration.
- **MerLin's backend does not escape the underlying combinatorial Fock-space growth** — it has less overhead per unit of that growth (build-once/reuse instead of Perceval's Analyzer rebuilding from scratch every call, plus autograd needing only 1 forward+backward pass vs. parameter-shift's 2-per-tracked-parameter), which let the dual-rail/native-autograd approach reach weight1 n=8 and mixed n=7 (vs. parameter-shift's n=6/n=5 CORE ceiling) — but it hits the same kind of wall once the Fock space is large enough: mixed n=8 (2n+2=18 modes, n+2=10 photons, `C(27,10)≈8.4M` states) took 2929s (~49 min) before failing with `MemoryError` *during `QuantumLayer` construction itself* (`merlin.pcvl_pytorch.slos_torchscript.SLOSComputeGraph._build_graph_structure`), never reaching a forward pass. n=9 was not attempted.
