<grounding_facts>
All five items below were independently verified in the planning session. The executor writes them
up. The executor does NOT re-derive them, does NOT re-search for them, and does NOT extend them.

1. **Van den Nest's formula** makes `<Z_a>` for an IQP circuit computable classically as
   `E_{z ~ Uniform}[cos(Phi(theta, z, a))]`. Consequence: training an IQP Born machine never needs to
   touch a quantum circuit or a simulator at all. Only *sampling* from the already-trained model
   needs the circuit. This project already names and cites this formula in `docs/iqp-baseline.md`;
   the attribution was independently confirmed on 2026-08-17 via Recio-Armengol et al.
   (arXiv:2503.02934), whose Proposition 1 derives the identical formula and cites "den Nest, 2010"
   (see `.planning/STATE.md`, Phase 18 verification note).

2. **The owner's sibling project** (`C:\Users\cuqui\iqp-mmd-barren-plateau`, docs at
   `docs/technical/learning-task.md` and `docs/technical/mmd-gaussian-fourier.md`) already implements
   exactly this: it trains an IQP Born machine entirely classically via the cosine formula, using a
   **Hamming-distance kernel** with bandwidth scaled per Rudolph et al. (arXiv:2305.02881) as
   `sigma in Theta(sqrt(n))`, giving `tau = tanh(1/(4*sigma^2)) ~ 1/n`. Its quantum circuit is only
   ever run to sample after training.

3. **This project's own `docs/iqp-baseline.md`** already cites Rudolph et al. and already flags a
   fixed (not n-scaled) kernel bandwidth as "a live methodological question for Phase 17's
   already-shipped result, not resolved by this doc alone" — written before v3.0 shipped, never
   acted on.

4. **What v3.0 actually did:** computed gradients by parameter-shift, executed twice per shifted
   parameter directly on the photonic circuit (calling Perceval), with a **fixed** `sigma=0.1` and a
   **Euclidean-distance** kernel over 2D spatial target-grid bins — not the Hamming/Fourier-mode
   kernel the sibling project and Rudolph et al.'s theorem are built on. The reason given at the time
   (already stated in this document's own Methodology paragraph) was that MerLin `QuantumLayer`
   autograd is structurally unavailable for this project's polarization-annotated circuits. That
   reason is true. It does not follow that parameter-shift-on-Perceval was the only remaining
   option: an IQP circuit's gradient is obtainable without touching a circuit simulator at all, via
   fact 1. That question was never asked before the method was chosen.

5. **This is a framing/context gap, not a numerical error.** No existing number, curve, closed form,
   fitted parameter, or verdict in either document is wrong or changes because of this.
</grounding_facts>
