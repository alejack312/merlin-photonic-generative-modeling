## Gap 1 (blocker) — baseline-TVD direction stated backwards

Three documents, including the external-facing README, state that both classically-easy-baseline TVDs *fall* as eta decreases. Re-read of the shipped CSVs during this audit:

| scope, n | eta 0.99 → 0.05 | `tvd_to_uniform` | `tvd_to_product_marginals` |
|---|---|---|---|
| weight1, n=6 | | 0.799 → 0.482 → 0.500 (falls, then ticks back up) | **0.029 → 0.500 (rises monotonically)** |
| mixed, n=2 | | **0.109 → 0.4997 (rises)** | **0.109 → 0.4997 (rises)** |
| mixed, n=4 | | 0.560 → 0.500 (falls) | **0.177 → 0.500 (rises)** |

`tvd_to_product_marginals` rises in **every** measured cell; `tvd_to_uniform` rises in mixed n=2. The correct statement is the one `docs/hardness-under-loss-study.md:176-190` already makes two paragraphs earlier — for weight-1, `product_marginals ≈ lossless`, so its TVD necessarily *tracks `tvd_to_lossless` upward*. The doc contradicts itself, and `README.md:86` compresses the wrong half into "TVD-to-classical-baselines fall as photon loss increases, as expected."

Flagged as a blocker rather than tech debt because it is a measured-result claim stated in the opposite direction on this project's most public surface, which is precisely what this project's founding "don't gloss over it" rule exists to prevent. The underlying data and code are correct — this is a write-up error, fixable in three files.
