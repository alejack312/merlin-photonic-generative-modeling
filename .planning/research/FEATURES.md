#### STUDY-01: Trainability / barren-plateau measurement

| Feature | Why Expected | Complexity | Notes |
|---------|--------------|------------|-------|
| Gradient computed via `torch` autograd through MerLin's `QuantumLayer`, not finite differences | MerLin's SLOS-based simulator is exact and differentiable end-to-end (same exactness property the weight-1/weight-2 TVD work already relies on, per `STACK.md`) — autograd gives the gradient with zero shot noise, matching this project's established preference for exact-over-sampled wherever available | LOW | `QuantumLayer` is a plain `torch.nn.Module`; `loss.backward()` + reading `.grad` per parameter is the entire mechanism. No new library. |
| Gradient-variance sweep across ≥3 system sizes (mode/qubit count `n`), each with ≥100 independent random parameter draws | This is McClean et al. (2018)'s standard protocol: variance of `∂L/∂θᵢ` estimated over many random initializations at each of several `n`, then examined for exponential-vs-polynomial decay — fewer than ~3 sizes cannot distinguish a decay shape at all, and fewer than ~100 draws gives a variance estimate too noisy to trust | LOW-MEDIUM | Reuses the project's existing weight-1 circuit builders directly; the new work is the sweep harness (loop over `n`, loop over seeds, collect `Var[∂L/∂θᵢ]`), not new circuit code. Compute cost grows with `n` (Fock-space mode count), so the practical max `n` this project can afford is a real, honestly-stated constraint — see the loop-in Pitfall 4 warning below. |
| Explicit poly-vs-exponential model comparison (e.g., linear fit of `log(Var)` vs `n` for the exponential hypothesis, power-law fit for the polynomial hypothesis; compare goodness-of-fit) | `docs/PITFALLS.md`'s Pitfall 4 and its cited precedent (arXiv:2605.11879, "Pre-Asymptotic Trainability in Photonic Variational Circuits under Postselection") document that eyeballing a log-variance plot at small `n` is a *known, measured trap in this exact photonic setting*: the same gradient-variance-vs-N curve looked polynomial-favored from N=2-10 and only "flipped decisively to exponential" once extended to N=24 | LOW | `scipy.optimize.curve_fit` (already installed, per `STACK.md`) for both fits; report which model fits better (R²/AIC), not a verbal impression of the plot. |
| Explicit statement of the parameter-initialization distribution swept (e.g., uniform on `[0, 2π)`) and, separately, of per-circuit "energy"/photon-number normalization if it varies across the sweep | `docs/iqp-baseline.md`'s own qubit-side finding: initialization scheme (small-angle vs. uniform) was the *load-bearing* variable determining plateau/no-plateau, not circuit structure alone (`plateau if small_angle OR (uniform AND n>=6 AND NOT complete_graph_like)`, 97.9% accuracy on 283 rows). `PITFALLS.md` Pitfall 4 separately flags that bosonic/photonic VQCs have a second hidden confound with no qubit analogue: gradient variance decays polynomially in per-mode "circuit energy," so a sweep that doesn't fix or report this is measuring an entangled, uninterpretable quantity | LOW | Both are reporting requirements on an otherwise-standard sweep, not new circuit work — but omitting either invalidates the comparison to this project's own qubit-side baseline. |
| Explicit statement of which generator set was swept (weight-1-only, or mixed weight-1+weight-2) and why | Weight-1 (deterministic `WP(θ,0)`) and weight-2 (probabilistic, herald-conditioned `heralded_cz`) are not the same mechanism, per `docs/iqp-photonic-encoding.md`'s own ENC-04 checkpoint ("a clean match on the deterministic case provides no evidence about the probabilistic case, because they don't share the property this test actually checked") — the same non-transfer logic applies to trainability, not just TVD | LOW | A scope statement, not new code; if only weight-1 is swept (likely, given compute/deadline pressure), say so plainly rather than let "the circuit" read as if it covers both. |
| Honest reporting of the sweep's max reachable `n`, and an explicit statement of whether the result is conclusive or is itself in the small-N range `PITFALLS.md` already flags as historically misleading | This project's established practice (CLAUDE.md's "Jul 25 is not a formality" / "report partial progress honestly" standing instruction, and the precedent of `results/phase7_neighbor_locality_summary.md`'s honest negative verdict) requires saying "we could only reach N=X, and X is inside/outside the range known to be reliable" rather than implying a conclusion the data doesn't support | LOW | This is a write-up/interpretation requirement (owner's job per CLAUDE.md), not code — but it gates whether STUDY-01 counts as "done" honestly, not just "done." |

#### ARB-01: Arbitrary-θ two-qubit diagonal phase gate

**Resolvability, stated directly (per this file's quality gate):** the parallel Stack-research thread already found and empirically verified that `perceval.components.core_catalog.controlled_rotation_gates.PostProcessedControlledRotationsItem` (catalog key `"postprocessed controlled gate"`) is a genuinely, continuously tunable `C...CZ(α)` gate already shipped in the installed `perceval-quandela==1.2.4` — confirmed both by direct source read and by live execution against the installed venv (a non-special angle, `α=π/3`, produced a `|1,1⟩`-branch phase of exactly 60.0° to floating-point precision, `STACK.md`). This research independently confirmed the gate's literature grounding: `arXiv:2405.01395`, **"Simple rules for two-photon state preparation with linear optics"**, is a real paper whose stated contribution explicitly includes "a construction for generalized post-selected n-qubit control-rotation gates" — this is a published, peer-reviewed-track construction, not an ad hoc engineering workaround. **ARB-01 is therefore not an open research question this milestone — the primitive-level question ("does a continuously-tunable gate exist and can it be built from Perceval's catalog") is already answered YES.** What remains is validation and integration work at the project's existing rigor bar, not gate discovery.

### Dependency Notes

- **ARB-01 is the only one of the three technical capabilities with no dependency on the other two** — it can be built, validated, and written up in parallel with STUDY-01/STUDY-02, and does not need either study's results to be meaningful. If sequencing under time pressure, ARB-01 is a safe candidate to finish first or run concurrently, since its "resolvability" question is already closed (see the ARB-01 table-stakes section above) and its remaining work is bounded, known-shaped validation.
- **STUDY-02's central claim is gated on a literature-reading task, not a code task.** The full read of arXiv:2510.24137 is cheap (a few hours) but load-bearing — without it, STUDY-02 cannot honestly state where this project's tested loss levels sit relative to the known threshold, which is the study's actual point. Flag this explicitly in planning as a near-zero-code, non-deferrable first step.
- **WRITE-01 cannot be meaningfully started before the other three have at least preliminary results**, but its *structure* (methodology-first, explicit scope statements, literature-comparison tables) can and should be drafted early, in parallel, as a template to fill in — this project's own precedent (`docs/iqp-photonic-encoding.md`'s ENC-01 through ENC-05 structure) shows the write-up skeleton is itself a design decision worth making before results exist, not an afterthought.
- **STUDY-01 and STUDY-02 share the compute-cost constraint** (Fock-space simulation cost growing with mode count) but are otherwise independent — a compute-budget decision (how large an `n` sweep is affordable) affects both and should be made once, not separately per study.
