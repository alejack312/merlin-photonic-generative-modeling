# Milestone v2.0: IQP → Photonic Encoding

**Status:** ✅ SHIPPED 2026-08-05
**Phases:** 8-9
**Total Plans:** 8

## Overview

Determine whether IQP's structural properties (trainability, sampling hardness) survive translation into a photonic/linear-optical ansatz — literature scoping and, if viable, a defensible on-paper encoding design. Implementation, the trainability/hardness study, and write-up were deliberately deferred to a follow-on milestone.

Source doc: `Post_Sept1_IQP_Photonic_Plan.md` — full 5-phase research plan (this milestone covered Phase 0-1 only).

**Details:**

## Milestone Summary

**Key Decisions:**

- Encoding target is discrete-variable (DV, Fock-space: phase shifters/beamsplitters/photon-counting), not continuous-variable (CV) — no published DV construction exists (genuinely novel), whereas Douce et al. (2017) already proved CV-IQP hardness (reproduction, not invention); DV also preserves IQP's native discrete bitstring-sampling character.
- v2.0 roadmap scoped to Phase 0-1 only (literature scoping + encoding design), not all 5 source-plan-doc phases — the plan doc itself says it "will get re-planned once Phase 0 lands," an explicit go/no-go gate.
- Polarization encoding (owner's choice, from personal coursework) over dual rail or QUDIT — corrected an inaccuracy in `09-RESEARCH.md`'s survey (Perceval does ship a polarization gate catalog: `HWP`/`QWP`/`PR`/`WP`/`PBS`).
- Runnable code and tests scoped to weight-1 IQP generators only; weight-2 derived on paper via the operator identity `CZ = exp(iπ/4·(I−Z_i−Z_j+Z_iZ_j))`, a real limitation of the available catalog gate rather than a design flaw.
- Validation metric: total variation distance (exact-vs-exact comparison), not MMD — MMD's kernel-bandwidth machinery exists to handle sampling noise that doesn't apply when both sides are exact calculations.
- Reference distribution: direct numpy state-vector simulation, not Van den Nest's cosine-formula trick (would need an extra transform step) or the sibling repo's `IqpSimulator` (disproportionate cross-repo dependency for n=2-3).

**Issues Resolved:**

- H/V port-labeling bug (self-consistent but physically backwards) caught via a direct bare-`PBS` calibration check during ENC-03's attempt-first checkpoint; fixed across the module, tests, and ENC-01's derivation text.
- A real inaccuracy in `09-RESEARCH.md`'s literature survey (claimed Perceval lacks a polarization gate catalog) corrected by direct source inspection.
- Phase 8's PREQ-01 gap (PS never exercised in the original fluency demo) closed by 08-04's Mach-Zehnder example.

**Issues Deferred:**

- Weight-2 (`heralded_cz`) implementation and testing — derived on paper only, explicitly named as the first item for any future implementation phase.
- `heralded_cz`'s exact success probability — confirmed real (Knill CZ, arXiv:quant-ph/0110144) but not independently recomputed; literature figures (1/9, ~2/27) cited as unverified for this specific gate.
- General-`n` scaling beyond the n=2,3 toy check.

**Technical Debt Incurred:**

- Phase 9 (Encoding Design) shipped without a standalone `gsd-verifier` VERIFICATION.md, unlike Phase 8. Closed post-audit via an independent `/gsd:verify-work 9` UAT pass (8/8, live-verified) rather than a formal verifier report — noted here as a process deviation for future milestones to avoid.
