# Milestone v2.1: Weight-2 Implementation

**Status:** ✅ SHIPPED 2026-08-06
**Phases:** 10-13
**Total Plans:** 6

## Overview

Implement and validate the weight-2 IQP generator (`heralded_cz`-based two-qubit diagonal phase gate, fixed at θ=π/4) that v2.0 designed on paper but never built or ran. Extend the classical-comparison validation pattern from weight-1 (TVD-based) to cover weight-2. Empirically measure `heralded_cz`'s actual success probability against Perceval's specific implementation, rather than relying on secondhand literature figures.

**Build order rationale:** de-risk the `heralded_cz` primitive standalone first (Phase 10) → build/verify the PBS-wrap/heralded_cz/PBS-unwrap insertion unit and compose the full weight-2 pipeline reusing existing weight-1 builders unmodified (Phase 11) → extend the exact reference and run TVD validation (Phase 12) → confirm weight-1/weight-2 composability in a mixed circuit (Phase 13). The existing 26-test weight-1 suite stayed green throughout — each phase included an explicit regression check before the next phase built on it.

## Phases

### Phase 10: Heralded-CZ Primitive De-Risking

**Goal**: `heralded_cz`'s actual measured behavior (not literature assumptions) is confirmed for this specific Perceval implementation, before any integration work begins.
**Depends on**: Phase 9 (reuses the polarization/dual-rail conventions `docs/iqp-photonic-encoding.md` established)
**Plans**: 1 plan

Plans:
- [x] 10-01: Herald-success probability + CZ phase-sign de-risking (`heralded_cz_derisking.py` + tests + docs update)

**Details:**
`heralded_cz` herald-success probability confirmed at exactly 2/27 (~0.074074), uniform across all 4 computational-basis inputs plus 2 superposition spot-checks, read from `global_perf`/`physical_perf`/`logical_perf` (never shot-sampled, via `build_experiment()` + `Processor.probs()`, never `build_circuit()` which drops the herald). CZ phase sign confirmed via `Simulator.prob_amplitude`: negative only on `|1,1⟩`, matching `diag(1,1,1,-1)`. `logical_perf` confirmed pure herald condition (empty `post_select_fn`, zero-leakage `Analyzer` truth table). Literature-comparison note added to `docs/iqp-photonic-encoding.md` (descriptive, no equality claimed against the previously-flagged literature figures 1/9 post-selected, ~2/27 heralded).

**Verified:** 4/4 must-haves (`10-VERIFICATION.md`). Full 32-test suite (26 pre-existing + 6 new) green, no regression.

### Phase 11: CZ Insertion Unit & Weight-2 Circuit Composition

**Goal**: The full weight-2 generator circuit is implemented — `PBS`→`heralded_cz`→`PBS` plus the two `WP(π/4,0)` single-qubit corrections — composed via `Processor`-level composition, reusing every existing weight-1 builder unmodified.
**Depends on**: Phase 10 (confirms the primitive behaves as assumed before building on it)
**Plans**: 2 plans (2 waves, sequential)

Plans:
- [x] 11-01: `build_cz_insertion(n, i, j)` — PBS-wrap → `heralded_cz` → PBS-unwrap, internal ctrl/data convention adapter, truth-table + superposition verification
- [x] 11-02: `build_weight2_processor(n, i, j, thetas)` — full Processor-level pipeline composition, additive π/4 theta folding, herald re-registration, non-regression snapshot check

**Details:**
`build_cz_insertion(n, i, j)` implemented as a local `Circuit(6)` (PBS-wrap → PERM-adapted `heralded_cz` → PBS-unwrap), truth-table verified against `diag(1,1,1,-1)` exactly across all 4 computational-basis combos plus 2 superposition spot-checks. The ctrl/data convention mismatch found in research (`heralded_cz` uses Perceval's own `Encoding.DUAL_RAIL` standard, the mirror image of this module's PBS-derived convention) resolved via an internal `PERM([1,0])` adapter — confirmed a convention mismatch between two independently-correct components, not a bug. `build_weight2_processor(n, i, j, thetas)` composes the full `Processor(2n+2)` pipeline via `Processor.add()`, reusing all four weight-1 builders unmodified (sha256 snapshot-verified); π/4 corrections fold additively into `build_diagonal_layer_circuit`'s `thetas`; heralds confirmed registered at exact global indices `{2n:1, 2n+1:1}` immediately after assembly. Discovered and documented a genuine Perceval library limitation carried forward to Phase 12: `Processor.probs()` crashes unconditionally when a registered herald is combined with any `PBS`-containing circuit.

**Verified:** 4/4 must-haves (`11-VERIFICATION.md`, independently re-executed). Full 107-test suite green, zero regressions.

**Plans**: 2 plans (2 waves, sequential — 12-02 depends on 12-01 for the actual measured numbers)

Plans:

**Details:**

Locked TVD gate at n=2, i=0, j=1, θ=π/4: TVD=2.581268532253489e-15, herald_failure_prob=0.9259259... (=1-2/27, matching Phase 10's measured success rate), residual=0.0. Upstream Perceval `add_herald`+`PBS` crash filed as [Quandela/Perceval#783](https://github.com/Quandela/Perceval/issues/783) (courtesy report — not on the critical path, since the workaround is already implemented and tested).

**Depends on**: Phase 12 (needs the validated weight-2 pipeline and exact reference to build the mixed-circuit test against)

## Milestone Summary

**Key Decisions:**

- Weight-2 built via `Processor`-level composition, not `Circuit`-level — `heralded_cz`'s `build_circuit()` alone drops the herald; only `build_experiment()`/`build_processor()` attach it. All four weight-1 builders reused with zero modification.
- Herald-free measurement variant (`_build_weight2_processor_no_herald`) built specifically to route around a confirmed, independently-reproduced Perceval library limitation (`Processor.add_herald()`+`PBS` crashing `Processor.probs()`) rather than assumed from a stack trace — filed upstream, worked around locally. **Correction (2026-08-07, see Issues Resolved below): the crash's scope was overstated at the time — this workaround remains correct and tested, but was likely broader than strictly required.**
- Weight-1/weight-2 composability tested with a weight-1 theta stacked directly on a weight-2 pair member, not disjoint qubits — the stronger test, proving a qubit's independent Z term and its ZZ pair participation compose correctly on the same qubit.
- Validation metric stayed total variation distance (exact-vs-exact), matching weight-1's established convention, rather than introducing a different metric for weight-2.

**Issues Resolved:**

- Perceval library crash (`Processor.add_herald()` + `PBS` → `Processor.probs()` matmul shape mismatch) confirmed via direct reproduction, worked around via a herald-free measurement path with manual post-selection, filed upstream as [Quandela/Perceval#783](https://github.com/Quandela/Perceval/issues/783).
  - **Correction (2026-08-07):** the original claim — "crash persists independent of ... annotation," i.e. unconditional whenever `add_herald()`+`PBS` are combined — was overstated and never re-verified after the research doc was written. Re-tested live against this same `perceval-quandela==1.2.4` venv, one day later, prompted by upstream maintainer pushback: the crash only occurs when the herald mode(s) are OMITTED from `Processor.with_input()` and left to auto-fill. Supplying the herald mode(s) explicitly (annotated or not) avoids the crash entirely — confirmed at n=2/n=3, multiple qubit pairs, using the actual `build_weight2_processor` production path with `add_herald()` registered. The herald-free measurement variant built to route around this remains correct and its 100+ dependent tests are unaffected, but the workaround was likely more conservative than strictly necessary. Full detail: `~/.claude/learnings/2026-08-06-perceval-polarizationsimulator-heralds-crash.md` (addendum) and `~/.claude/learnings/2026-08-07-verify-before-filing-external-bug-reports.md`.
- Real silent-bug risk: `PolarizationSimulator`'s default `{P:H}` ancilla annotation gave silently wrong (non-crashing) probabilities when fed real superposition input — fixed by explicitly annotating ancilla photons `{P:V}`, confirmed against a trusted PBS-free ground truth to TVD~1e-16.
- Design-doc staleness (`docs/iqp-photonic-encoding.md` still said weight-2 was unimplemented after Phase 11's own edit, because Phases 12-13 never touched it) — found by the milestone audit's integration checker, fixed within the audit rather than deferred.

**Issues Deferred:**

- ARB-01 (arbitrary-θ weight-2) — `heralded_cz` is a fixed, non-parameterized catalog gate; no known decomposition realizes arbitrary θ from this catalog alone. Genuinely open research, not an implementation gap.
- STUDY-01/STUDY-02/WRITE-01 (trainability study, hardness-under-loss assessment, write-up) — now unblocked since weight-2 is confirmed working, but not attempted this milestone by design.

**Technical Debt Incurred:**

None outstanding. The one item found during this milestone (design-doc staleness) was fixed within the milestone audit itself, before archiving.
