    Before Claude writes any code, here is the low-level Perceval API needed for this demo (verified directly against this repo's installed `perceval-quandela==1.2.4` in `08-RESEARCH.md`):

    - `import perceval as pcvl` — `Circuit`, `BS`, `PS`, `BasicState`, `Processor` all live at the top-level namespace.
    - `from perceval.algorithm import Analyzer` — `Analyzer` is NOT exported at the top-level; must be imported explicitly from `perceval.algorithm`.
    - **Building a circuit:** `pcvl.BS.H()` gives the Hadamard-convention 50/50 beamsplitter (real-valued matrix `[[1,1],[1,-1]]/√2`) — safer for hand-deriving closed-form checks than the default `BS()` (Rx convention, complex-valued, `i` on cross terms). Both split single-photon probability 50/50, but differ in phase for multi-photon interference.
    - **Running it:** `Analyzer` requires a `Processor`, not a bare `Circuit` — wrap first: `proc = pcvl.Processor("SLOS", circuit)` (`"SLOS"` = the standard exact-simulation backend).
    - **Input states:** `pcvl.BasicState([1, 0])` (list form) — e.g. `[1, 0]` means one photon in mode 0, vacuum in mode 1.
    - **Computing output probabilities:** `analyzer = Analyzer(proc, [input_state], "*")` (the `"*"` computes all reachable output states), then `analyzer.compute()`, then read `analyzer.distribution` and `analyzer.output_states_list`.
    - **Closed-form facts to check against:** a single photon on a 50/50 beamsplitter has exactly 50% chance of exiting either port (no interference possible with one photon). Two indistinguishable photons, one per input port, on a 50/50 beamsplitter always bunch into the same output port — the Hong-Ou-Mandel effect — giving `P(1,1)=0`, `P(0,2)=P(2,0)=0.5`.
