  <behavior>
    Given `p_real` (a length-`2**n` numpy array, non-negative, sums to 1 -- exactly
    `target_grid.make_target_grid(n)`'s second return value), compute deterministic circuit
    parameters with no random component at all.

    **Bit-ordering convention (this IS the load-bearing correctness question, per Pitfall 3):**
    `target_grid.py::make_target_grid`'s `bin_index_fn(bitstring) = int(bitstring, 2)` treats
    `bitstring[0]` (leftmost char) as the bitstring's MOST significant bit, and
    `iqp_photonic_encoding.py::fock_to_bitstring` builds that string left-to-right in qubit order
    (qubit 0 first). So bit `k` (qubit `k`'s value) sits at bit-position `n-1-k` (0-indexed from
    the LSB) of the integer bin index: `bit_k(bin_index, k, n) = (bin_index >> (n-1-k)) & 1`.

    Cases (input -> expected output), all as pytest tests:

    1. **Bit-ordering spot-check (Pitfall 3's specific test, mandatory):** for `n in [2, 3, 4]`,
       for every `k in range(n)`, build the bitstring with a single `"1"` at position `k` (e.g.
       `n=3, k=1` -> `"010"`), compute `idx = int(bitstring, 2)`, and assert
       `bit_k(idx, k, n) == 1` while `bit_k(idx, kk, n) == 0` for every other `kk != k`. This
       proves `bit_k` is the exact inverse of `bin_index_fn`'s own `int(bitstring, 2)` convention
       for every qubit position, not just position 0 or n-1.

    2. **`empirical_mean_bit` worked example:** `p_real = np.array([0.1, 0.2, 0.3, 0.4])` (n=2, so
       indices 0,1,2,3 correspond to bitstrings "00","01","10","11"). Bit 0 (leftmost char, qubit
       0) is 1 for indices 2,3 -> `empirical_mean_bit(p_real, 0, 2) == pytest.approx(0.7)`. Bit 1
       (qubit 1) is 1 for indices 1,3 -> `empirical_mean_bit(p_real, 1, 2) == pytest.approx(0.6)`.

    3. **`weight1_data_dependent_theta` worked example:** same `p_real` as above,
       `weight1_data_dependent_theta(p_real, 2)` returns
       `[np.arcsin(np.sqrt(0.7)), np.arcsin(np.sqrt(0.6))]` (approx, list of 2 floats, in qubit
       order 0 then 1).

    4. **`empirical_pm1_covariance` worked example:** same `p_real`. In the {-1,+1} convention
       (`z = 2*bit - 1`): `z0 = [-1,-1,+1,+1]`, `z1 = [-1,+1,-1,+1]` across indices 0..3.
       `E[z0*z1] = 0.1*1 + 0.2*(-1) + 0.3*(-1) + 0.4*1 = 0.0`. `E[z0] = -0.1-0.2+0.3+0.4 = 0.4`.
       `E[z1] = -0.1+0.2-0.3+0.4 = 0.2`. `Cov = E[z0*z1] - E[z0]*E[z1] = 0.0 - 0.08 = -0.08` ->
       `empirical_pm1_covariance(p_real, 0, 1, 2) == pytest.approx(-0.08)`.

    5. **`weight2_data_dependent_theta` worked example:** same `p_real`,
       `weight2_data_dependent_theta(p_real, 0, 1, 2, scale_factor=1.0) == pytest.approx(-0.08)`
       and `weight2_data_dependent_theta(p_real, 0, 1, 2, scale_factor=2.0) == pytest.approx(-0.16)`
       (scale_factor multiplies linearly).

    6. **Domain safety:** `weight1_data_dependent_theta` never raises for `p_real` values at the
       arcsin domain boundary (bit-marginal exactly 0.0 or 1.0 -- both are valid probabilities, so
       `arcsin(sqrt(...))` is always well-defined here; no clipping/guard needed, per
       17.1-RESEARCH.md's explicit note on this). Test with a p_real concentrating all mass on one
       bin (a bit-marginal of exactly 0.0 for some k and 1.0 for others).

  <implementation>
    `trainability/data_dependent_init.py` (pure numpy, no torch, no dependency on
    `trainability.target_grid` or any other project module -- callers pass `p_real` in directly,
    matching this package's existing single-concern-per-module convention:
    `mmd_exact.py`/`param_shift.py`/`target_grid.py`/`rng.py`/`stats.py`/`curve_fit.py` are all
    single-purpose files with no cross-imports beyond numpy):

    ```python
    import numpy as np

    def bit_k(bin_index: int, k: int, n: int) -> int:
        """Qubit k's bit value within a bin index built by bin_index_fn(bitstring) =
        int(bitstring, 2), where bitstring[k] corresponds to qubit k (MSB-first, matching
        trainability/target_grid.py's convention)."""
        return (bin_index >> (n - 1 - k)) & 1

    def empirical_mean_bit(p_real: np.ndarray, k: int, n: int) -> float:
        """P(bit k == 1) under p_real -- this project's stand-in for Recio-Armengol et al.'s
        <x_j> = mean of the jth dimension of the training data (arXiv:2503.02934, Sec 8.1.2)."""
        idx = np.arange(2 ** n)
        bits_k = (idx >> (n - 1 - k)) & 1
        return float(np.sum(p_real * bits_k))

    def weight1_data_dependent_theta(p_real: np.ndarray, n: int) -> list:
        """arcsin(sqrt(<x_k>)) per qubit k -- the paper's single-qubit-gate init rule."""
        return [float(np.arcsin(np.sqrt(empirical_mean_bit(p_real, k, n)))) for k in range(n)]

    def empirical_pm1_covariance(p_real: np.ndarray, j: int, k: int, n: int) -> float:
        """Cov(z_j, z_k) under p_real, z in {-1,+1} convention (the paper converts binary
        training data to +-1 before computing this)."""
        idx = np.arange(2 ** n)
        zj = 2 * ((idx >> (n - 1 - j)) & 1) - 1
        zk = 2 * ((idx >> (n - 1 - k)) & 1) - 1
        return float(np.sum(p_real * zj * zk) - np.sum(p_real * zj) * np.sum(p_real * zk))

    def weight2_data_dependent_theta(p_real, i, j, n, scale_factor) -> float:
        """scale_factor * Cov(z_i, z_j) -- the paper's two-qubit-gate init rule; scale_factor is
        the paper's own free hyperparameter (their Table 2 searched [0.0001, 1.0])."""
        return scale_factor * empirical_pm1_covariance(p_real, i, j, n)
    ```
