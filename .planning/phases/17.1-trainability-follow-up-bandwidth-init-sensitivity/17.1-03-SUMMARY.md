- `pooled_gradients_for_cell`/`run_gradient_variance_sweep` gained a `scale_factor` keyword parameter (default 1.0, backward-compatible), threaded exactly like `sigma` was in Plan 17.1-02.

## Files Created/Modified

- `trainability/sweep.py` - `data_dependent_init` import; `scale_factor` keyword parameter on both public functions; `fixed_thetas` computed once per cell (with the mixed-scope override) before the draw loop; draw loop now branches on `init_scheme == "data_dependent"` instead of unconditionally calling `sample_thetas`.

- `tests/test_sweep.py` - 3 new tests: (a) `test_pooled_gradients_data_dependent_is_identical_across_draws` proves determinism across 5 draws; (b) `test_pooled_gradients_mixed_data_dependent_overrides_pair_indices` proves the mixed-scope override actually swaps in the covariance-based theta for indices `i,j` (not just that some data-dependent scheme runs) by independently reproducing the gradient computation with and without the override and comparing against the sweep's actual output; (c) `test_sweep_data_dependent_weight1_returns_expected_shape` confirms `run_gradient_variance_sweep` still returns the standard stats-dict shape under the new scheme.

## Decisions Made

- **Mixed-scope override target:** confirmed at the code level (`iqp_photonic_encoding.py`'s `photonic_weight2_iqp_distribution` docstring) that `thetas[i]`/`thetas[j]` are the same variables serving as both qubit i/j's weight-1 phase and the weight-2 gate's input (folded with `+pi/4` internally). Given this circuit has no independent weight-2-only parameter, the chosen translation (stated in the plan, now implemented and tested) is: `i,j` get the covariance-based value; every other qubit keeps its own arcsin value. This will be restated in `docs/trainability-study.md` by Plan 17.1-06 so the owner can override on review if needed.
- **Where to special-case `data_dependent`:** entirely inside `pooled_gradients_for_cell`, not inside `sample_thetas` -- because it needs `p_real` and `weight2_pair`, which `sample_thetas`'s `(rng, n, init_scheme)` signature doesn't carry, and because unlike the other two schemes it has no per-draw randomness to sample.
- **`scale_factor` default:** 1.0, per 17.1-RESEARCH.md's owner decision, threaded as a no-op for every scope/init combination except `mixed` + `data_dependent`.
