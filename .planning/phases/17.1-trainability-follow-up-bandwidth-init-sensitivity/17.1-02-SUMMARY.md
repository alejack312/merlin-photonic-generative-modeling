# Phase 17.1 Plan 02: Sigma Threading & Bin-Spacing Reporting Summary

**Threaded an explicit, backward-compatible `sigma` kernel-bandwidth parameter through `trainability/sweep.py` and `gradient_variance_sweep.py`'s CLI, plus a `target_grid.bin_spacing(n)` reporting helper, with a structural fix (sigma embedded in chunk filenames) so chunk/combine sigma mismatches fail loudly instead of silently corrupting results.**

## Performance

- **Duration:** ~15 min
- **Completed:** 2026-08-12
- **Tasks:** 2/2
- **Files modified:** 4

## Accomplishments
- `pooled_gradients_for_cell`/`run_gradient_variance_sweep` gained an optional `sigma` parameter (default: the existing `SIGMA=0.1` module constant), passed straight through to `mmd_exact.gaussian_kernel_matrix_np` in place of the bare module global -- proven bit-identical to the old hardcoded behavior for every zero-argument-changed caller.
- `target_grid.bin_spacing(n)` added as a pure reporting helper (nearest-neighbor bin-center spacing at a given n), matching the hand-verified table from 17.1-RESEARCH.md (n=2 -> 1.2, n=6 -> 0.1714).
- `gradient_variance_sweep.py` gained a `--sigma` CLI flag (default 0.1) and now records `sigma`/`bin_spacing` as explicit columns in every CSV row across all three code paths (`run`, `run_chunk`, `combine_chunks`).
- Chunk/combine sigma-mismatch structurally caught: sigma is embedded in chunk filenames and `combine_chunks`' glob pattern, so a mismatched `--sigma` between chunking and combining now raises `FileNotFoundError` instead of silently pooling gradients computed under different kernels (17.1-RESEARCH.md Pitfall 2).

## Decisions Made
- `sigma` remains a keyword-with-default everywhere, never a required parameter -- this is the entire correctness guarantee behind Pitfall 1 (Phase 17's already-shipped CSVs and test suite must stay bit-identical). Verified explicitly, not assumed: `test_pooled_gradients_sigma_default_matches_explicit_old_value` asserts `sigma=0.1` passed explicitly produces the exact same array as `sigma` omitted.
- `bin_spacing` is reporting-only, never fed back into sigma computation -- matches 17.1-RESEARCH.md's locked design that TRAIN-09 uses one fixed sigma per sweep run (owner-decided grid `{0.03, 0.1, 0.3, 1.0, 3.0, 9.0}`), not a bin-spacing-derived schedule.
