<objective>
Build the weight-1 loss-sweep core function -- `photonic_iqp_distribution_lossy(n, thetas, eta)` -- the primitive HARD-01 requires: photon loss applied via `pcvl.LC(loss)` component insertion into a `Processor`, NOT via the `noise=NoiseModel(...)` constructor parameter (18-RESEARCH.md Pitfall 1, CONFIRMED: `NoiseModel` silently no-ops on this project's polarization-annotated circuits, for any η). Two load-bearing gotchas from `18-RESEARCH.md` must be baked into this function and proven by dedicated tests, not left implicit:

1. **Pitfall 1** -- `Processor(..., noise=NoiseModel(transmittance=η))` silently reproduces the lossless result for this project's `{P:H}`/`{P:V}`-annotated circuits. Loss MUST be applied via `proc.add(mode, pcvl.LC(loss))` on every mode, inserted before the circuit itself.
2. **Pitfall 2** -- `LC`-based loss requires an explicit `proc.min_detected_photons_filter(0)` call. Without it, `Processor`'s automatic filter (which only inspects `NoiseModel`, blind to `LC` components) silently discards every lossy branch, producing a plausible-looking but meaningless loss-invariant "normalized" distribution. `global_perf` still correctly reports true survival probability even when this bug is silently present -- do not rely on `sum(results.values()) ~= 1` alone as a sanity check.

Also builds HARD-02's cross-check: since `NoiseModel` cannot be run end-to-end on this project's real polarization circuits (Pitfall 1), the honest cross-check (per `18-RESEARCH.md`'s explicit recommendation) is confirming `NoiseModel` and `LC` agree with each other on a shared, simplified, non-polarization toy circuit where both mechanisms are actually applicable.

Purpose: this is the foundational primitive every later plan in this phase depends on -- Plan 18-05's sweep integration, Plan 18-06's real sweep run, and every downstream TVD/anticoncentration number in Plans 18-07/18-08 trace back to this function being correct.
Output: `hardness/loss_model.py` (new package), with a passing TDD test suite proving both pitfalls are avoided (not just asserted-away) and HARD-02's cross-check passes.
</objective>
