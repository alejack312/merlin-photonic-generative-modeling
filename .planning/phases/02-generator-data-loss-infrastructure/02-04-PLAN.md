  <name>Task 1: Implement closed-form MMD² loss with precomputed kernel matrices (GEN-05)</name>
  <files>generator/mmd.py</files>
  <action>
    Create `generator/mmd.py` implementing RESEARCH.md Pattern 3 exactly:

    ```python
    import torch

    # Proposed sweep bracketing the verified ring gap (0.1) and grid spacing (~0.063)
    # over the padded [-0.1, 1.1]^2 bin-center grid. Not a locked final value — Phase
    # 4 evaluates these against actual visual/structural ring recovery.
    SIGMA_GRID = [0.02, 0.05, 0.1, 0.2, 0.4]

    def gaussian_kernel_matrix(centers: torch.Tensor, sigma: float) -> torch.Tensor:
        """centers: (K,2). Returns (K,K) Gram matrix. Compute once per sigma; reuse every step."""
        sq_dists = torch.cdist(centers, centers, p=2) ** 2
        return torch.exp(-sq_dists / (2 * sigma ** 2))

    def mmd2(p: torch.Tensor, q: torch.Tensor, kernel_matrix: torch.Tensor) -> torch.Tensor:
        """p, q: (K,) probability vectors. kernel_matrix: (K,K), precomputed.
        Returns scalar tensor. Gradients flow through q only (p is expected to be
        the fixed p_real with requires_grad=False)."""
        pp = p @ kernel_matrix @ p
        qq = q @ kernel_matrix @ q
        pq = p @ kernel_matrix @ q
        value = pp + qq - 2 * pq
        # Defensive: MMD^2 is provably >=0 for a PSD kernel (Gaussian is PSD);
        # this clamp guards against float32 rounding noise at K=400 scale.
        return torch.clamp(value, min=0.0)
    ```

    Do not recompute the kernel matrix inside `mmd2()` — it must be precomputed once (per σ) and passed in, both here and in the test suite (RESEARCH.md Anti-Patterns).

  <name>Task 2: Write pytest suite for MMD² — finiteness, self-comparison, and gradient flow</name>
  <files>tests/test_mmd.py</files>
  <action>
    Create `tests/test_mmd.py` covering, for each `sigma` in `SIGMA_GRID` (parametrize with `@pytest.mark.parametrize("sigma", SIGMA_GRID)` where practical):

    1. **Kernel matrix sanity:** `gaussian_kernel_matrix(centers, sigma)` is shape `(400, 400)`, symmetric (`torch.allclose(K, K.T)`), all values in **non-strict `[0, 1]`** (use `(K >= 0).all() and (K <= 1).all()`, NOT a strict `(0, 1]` check), diagonal ≈ 1.0. Do not assert strict positivity off-diagonal: over the padded `[-0.1,1.1]²` grid (max pairwise distance ≈1.697), at small σ (0.02, and likely 0.05) the exponent `-dist²/(2σ²)` reaches deeply negative values (e.g. ≈-3600 at σ=0.02 for far-apart bin-center pairs) that underflow to exactly `0.0` in float32 (underflow threshold ≈ exponent -87.3). Exact-zero off-diagonal entries at small σ are expected float32 underflow, not a bug in the kernel formula — a strict `(0, 1]` assertion would deterministically fail at σ=0.02 (and likely σ=0.05) for reasons unrelated to correctness.
    2. **Finite & non-negative over random trials:** generate ~50 random probability vector pairs `(p, q)` over K=400 (e.g. `torch.rand(400)` normalized to sum to 1) and assert `mmd2(p, q, K)` is finite (`torch.isfinite`) and `>= 0` for every trial and every σ.
    3. **Self-comparison ≈ 0 (the critical sanity check):** using the real `p_real` from `generator.data` (via `load_circles_data()` + `compute_p_real()` + the same `bin_centers`), assert `mmd2(p_real, p_real, K).item() == pytest.approx(0.0, abs=1e-5)` for every σ in the sweep — a fundamental MMD property; catches a broken kernel/formula before it reaches Phase 3.

This is the same gradient-flow property RESEARCH.md verified directly (`p @ K @ q` differentiates through `q` via ordinary matmul) — this test proves it holds for this project's actual `p_real`/circuit combination, not just the abstract math.
