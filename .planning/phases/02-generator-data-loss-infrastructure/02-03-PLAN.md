Return `(X_train_normalized, X_test_normalized)` as `torch.float32` tensors — do not shuffle/reseed differently from quickstart.py, since reproducibility here matters for both this phase's own determinism check and consistency with Phase 1's verified pipeline.

    2. `compute_p_real(data_xy: torch.Tensor, bin_centers: torch.Tensor) -> torch.Tensor` — implement RESEARCH.md Pattern 2 exactly (nearest-bin-center histogram via `torch.cdist` + `argmin` + `torch.bincount`, normalized by total count):

    ```python
    def compute_p_real(data_xy: torch.Tensor, bin_centers: torch.Tensor) -> torch.Tensor:
        """data_xy: (N,2) points already in the bin-centers' coordinate space.
        bin_centers: (K,2). Returns (K,) probability vector: non-negative, sums to 1.
        Uses nearest-bin-center assignment (not grid-edge histogram) so p_real's
        binning convention is identical to the kernel's — same distance machinery,
        same source-of-truth grid (see 02-RESEARCH.md Pattern 2 / Anti-Patterns)."""
        dists = torch.cdist(data_xy, bin_centers, p=2)
        nearest = dists.argmin(dim=1)
        counts = torch.bincount(nearest, minlength=bin_centers.shape[0]).float()
        return counts / counts.sum()
    ```

    Note: `compute_p_real` takes `bin_centers` as a parameter — `generator/data.py` itself does not import `make_bin_centers` from `generator.bin_centers`. Callers (Task 2's test file) are responsible for constructing the bin-center grid and passing it in.

    Use `X_train` only when computing `p_real` at call sites/tests in this plan — not `X_train + X_test` combined. This is deliberate (per 02-RESEARCH.md's Open Question 3 recommendation): keeps `X_test` genuinely held out for Phase 5's benchmark rather than baked into the Phase 3 training target.
