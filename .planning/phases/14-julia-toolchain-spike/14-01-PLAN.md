  <name>Task 1: Install Julia toolchain (juliaup + Julia 1.10 LTS)</name>
  <files>N/A — system-level toolchain install, no repo files modified in this task</files>
  <action>
Install juliaup and pin Julia to the 1.10 LTS channel (not `release`/beta — research found Windows precompilation failures cluster on newer/beta versions).

**Primary path:**
```
winget install --id=Julialang.Juliaup -e
```
After it reports success, open work in a fresh shell/process (PATH changes require this) and run:
```
julia --version
```
Expect output like `julia version 1.10.x`. If `julia` is not found even after a fresh process, check `where julia` / `Get-Command julia -ErrorAction SilentlyContinue` before concluding install failed — juliaup sometimes needs one more shell restart to propagate PATH.

If `julia --version` resolves, pin LTS explicitly:
```
juliaup add lts
juliaup default lts
julia --version    # re-confirm it now reports the LTS version
```

**If the primary path fails** (winget install errors out, OR `julia`/`juliaup` still isn't resolvable after a retry in a fresh shell) — this is very likely Windows antivirus/endpoint protection quarantining juliaup's unsigned binaries (a confirmed, filed upstream issue: `JuliaLang/juliaup#736`). Check Windows Security quarantine/protection history for a blocked juliaup/julia executable around the install time before assuming a different cause.

**One alternate path (per CONTEXT — try exactly once, then stop):** download the official Windows x64 Julia installer directly from https://julialang.org/downloads/ (confirm the current LTS filename on that page, since it may have moved since research was written — research's reference point was `julia-1.10.11-win64.exe`), then run it silently:
```
julia-installer.exe /VERYSILENT /NORESTART /ADDTOPATH=1
```
(Inno-Setup-based installer; this also installs juliaup under the hood in current Julia releases, per research.) Re-run `julia --version` in a fresh shell to confirm.

**If this alternate path also fails:** this is a full no-go for the entire spike (per CONTEXT — Yao.jl/BosonSampling.jl are never reached if `juliaup`/`julia` itself cannot be installed). Do not attempt a third install method. Skip directly to Task 3's summary-writing step and record a full no-go with the exact errors observed from both attempts, then stop — do not attempt Task 2.
  </action>
  <verify>`julia --version` succeeds in a fresh shell/process and reports a 1.10.x version. `juliaup status` (or equivalent) confirms `lts` is the default channel.</verify>
  <done>Julia 1.10 LTS is installed and callable as `julia` from this project's shell, OR a full no-go is recorded per the escalation above and Tasks 2-3's circuit work is skipped in favor of Task 3's summary-only step.</done>
