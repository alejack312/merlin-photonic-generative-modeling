    **Four candidate encoding schemes** (all natively representable in Perceval, per `09-RESEARCH.md`'s survey — condensed here):

    | Scheme | Modes | `\|+⟩` start | Diagonal layer | Conjugation | The hard part |
    |---|---|---|---|---|---|
    | **Dual rail** (`Encoding.DUAL_RAIL`) | 2 per qubit | `BS.H()` per qubit — literally the same component `perceval_fluency_demo.py`'s MZI example already uses | Single-qubit generators: `PS` on rail 1 (shipped in `gates_1qubit.py`). Multi-qubit generators: no deterministic gate exists — only heralded/post-selected CZ (`heralded cz`, `postprocessed cz` in `core_catalog`), probabilistic, success probability <1 | `BS.H()` again per qubit | Multi-qubit (weight-≥2) diagonal terms need probabilistic gates — a real, literature-known cost (KLM), not something to gloss over |
    | **QUDIT one-hot** (`Encoding.QUDIT2`...`QUDIT7`) | `2^n` total (whole register = 1 photon) | equal superposition of 1 photon across all `2^n` modes | trivial — one `PS` per mode, since the full bitstring IS the mode index and any Z-diagonal operator is diagonal in the mode basis too | full `2^n×2^n` unitary via `pcvl.Unitary`/`GenericInterferometer` — deterministic, no ancillas needed | conjugation is deterministic but costs exponentially many modes/components in n — not a scalable "general n" construction, must be stated as a caveat |
    | **Single-rail** (`Encoding.RAW`) | 1 per qubit | needs a borrowed reference mode to do anything phase-like (a bare `PS` is invisible without an interference partner — see `perceval_fluency_demo.py`'s MZI derivation) | same borrowed-mode issue | same | a citable no-go result (Wu, Walther, Lidar 2013, arXiv:1107.4646): passive linear optics can't simultaneously give deterministic entangling gates and suppress two-photon bunching |
    | **Polarization** (`Encoding.POLARIZATION`) | 1 per qubit, 2 polarization DOF | analogous to dual rail | analogous to dual rail | analogous to dual rail | mathematically dual rail's twin, but Perceval has no polarization-specific gate catalog — you'd derive gates from scratch by analogy rather than reuse `gates_1qubit.py` |

    (GKP, time-bin, and frequency-bin encodings are ruled out on toolkit grounds — Perceval has zero continuous-quadrature primitives, and no native time-bin/frequency-bin component; not presented as live options.)

    **Perceval API you'll need** (verified against this repo's installed `perceval-quandela==1.2.4`):
    - `pcvl.BS.H()` — Hadamard-convention beamsplitter, already verified in `perceval_fluency_demo.py`.
    - `pcvl.PS(theta)` — phase shifter; invisible under Fock-basis measurement without a second beamsplitter to interfere against (already derived via the MZI example).
    - `perceval.components.core_catalog.gates_1qubit` — dual rail's shipped `h`, `s`, `t`, `z`, `x`, `rx`, `ry`, `rz` circuits — reuse, don't re-derive.
    - `perceval.components.core_catalog.{heralded_cz, postprocessed_cz, heralded_cnot, postprocessed_cnot}` — dual rail's shipped multi-qubit gates, with their herald/post-select conditions already encoded.
    - `pcvl.Unitary(matrix)` / `pcvl.GenericInterferometer` — drop in or decompose an arbitrary `m×m` unitary (relevant if QUDIT is chosen, for the `H^⊗n` conjugation mesh).
    - `pcvl.Circuit(m)`, `circuit.add(start_port_index, component)` (int start index, not a range), `pcvl.Processor("SLOS", circuit)`, `Analyzer(proc, [input_states], "*")` → `.compute()` → `.distribution`/`.output_states_list` — the exact pattern `perceval_fluency_demo.py` already uses and verifies.
