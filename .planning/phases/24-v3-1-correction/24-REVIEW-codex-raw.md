# Null-result review

- **FAIL: trainability correction overstates the identity-kernel null** (`docs/trainability-study.md:31-43`, `README.md:29`, `tests/v3_correction/test_null_results.py:285-292`). The no-photonics null is the product distribution (or that product plus the fixed pair for `mixed`) evaluated with the actual Gaussian kernel. For `sigma=0.1`, the kernel is effectively diagonal at n<=4, but the grid spacing at n=5-6 is `0.171428...`, giving an off-diagonal value `exp(-d^2/(2 sigma^2)) = 0.230066...`, not numerical zero. The test only covers n=2,3,4. The “no photons are needed” diagnosis is supported only approximately by the null model; the stated “plain L2 at every swept n” mechanism does not survive.

- **PARTIAL: “reproduces the shipped curve” is too strong** (`docs/trainability-study.md:35`, `tests/v3_correction/test_null_results.py:127-152,261-282`). The regression uses finite differences, 2,000 random draws, and a relative tolerance of 0.5 on adjacent variance ratios; it skips n=2. Measured null relative errors reach about 38.6% (weight1, sigma=0.1, n=5->6). This establishes a directionally matching no-photonics control, not a closed-form or floating-point reproduction of the whole curve.

- **UNVERIFIED / narrative repair: “not a barren plateau by construction”** (`docs/trainability-study.md:37`, `docs/technical-findings.md:9`, `README.md:29`). The null itself produces the observed exponential variance decay, approximately from a product-distribution metric. It therefore supports “not attributable to the photonic circuit” or “not circuit-specific”; it does not prove the categorical semantic claim that a product distribution cannot count as a barren-plateau-style metric signature.

- **UNVERIFIED: the high-sigma re-emergence is called a second artifact without a null check** (`docs/trainability-study.md:39`). The relevant null would evaluate the same no-photonics model at sigma=3 and 9 and compare its fitted verdicts to the reported rows. `test_null_results.py` only checks sigma<=0.1, so “exactly what this mechanism predicts” and “not a returning trainability signal” are not established.

- **UNVERIFIED: corrected max-n performance claim** (`docs/trainability-study.md:66`). The current full-register simulator ceiling being an implementation choice is supported by the factorization argument and the separate dual-rail n=7-8 run. “n in the 20s in milliseconds” is an unrun performance extrapolation: no structured polarization simulator or n=20-24 benchmark exists here. The dual-rail run is a different encoding and method, so it is not a direct null or benchmark for that proposed implementation.

- **PASS as a pipeline null, not a hardness result: TVD formulas** (`docs/hardness-under-loss-study.md:22-34`, `tests/v3_correction/test_null_results.py:71-123`). If the reported lossy vector is `s*p_lossless`, then `TVD=1/2(1-s)`. The derived nulls are `s=eta^n` for `weight1`, and `s=(2/27)*eta^(n+2)/h(eta)` for `mixed`, with `h=(2/27)eta^4+(8/27)eta^3(1-eta)+(10/27)eta^2(1-eta)^2`. The primary polarization CSVs match to `7.2e-15`; the dual-rail CSVs differ by up to `3.8e-6`, still inside the test's loose `2e-3` absolute tolerance. The result is a verified metric/survival null, not evidence that the circuit is hard.

- **UNVERIFIED: “exactly as hard as the lossless case”** (`docs/hardness-under-loss-study.md:36`, `docs/technical-findings.md:10`, `README.md:31`). The null establishes conditional distribution identity, `p_conditional = p_lossless`. It does not establish either distribution's computational hardness, and no complexity proof or hardness measurement is supplied. The defensible claim is “conditional output is unchanged”; “exactly as hard” is a new hardness assertion smuggled in after the artifact was removed.

- **PASS only as a shape-statistic null: anticoncentration invariance** (`docs/hardness-under-loss-study.md:34,153-155,351-359`, `docs/technical-findings.md:63`). If conditioning leaves the shape unchanged, `alpha=2^n sum(p_x^2)` is unchanged too. That survives as a consequence of the reporting pipeline. It is not an independent circuit result, and `test_null_results.py` does not test alpha itself.

- **FAIL / PARTIAL: throughput wording and scope** (`docs/hardness-under-loss-study.md:36-53`). The table's cells correctly compute `1/p` for `p=eta^(n+2k)(2/27)^k` under the explicitly chosen all-photons-survive event. But line 36 calls `p` itself “samples per useful shot,” although `p` is a probability and `1/p` is the expected sample count. Also, the “mixed-scope closed form above” is a conditional-survival fraction, not the raw throughput probability. For k>=2 the table is an illustrative independent-gate extrapolation, explicitly not a measured or cross-gate-compounded result; it must not be presented as established throughput data.

- **FAIL: the supporting TVD explanation contradicts the implementation** (`docs/hardness-under-loss-study.md:149`, `src/merlin_iqp/encoding/iqp_photonic.py:1029-1033`, `src/merlin_iqp/hardness/sweep.py:188-196`). The code computes TVD directly on the sub-normalized lossy `dist` and normalized reference, which is exactly why the null is `1/2(1-s)`. It does not independently normalize the lossy distribution as the prose says. That sentence should not be retained alongside the closed-form derivation.

- **UNVERIFIED: corrected encoding “original work” claim** (`docs/iqp-photonic-encoding.md:3-7`). The null is that KLM already supplies the general dual-rail/heralded-linear-optics realization, so the project contributes no new general universality result. The n=2-3 tests can establish correctness of this particular mapping and conventions; they cannot establish originality. “Genuine, careful, original work” remains a literature-priority claim, not a checked result.

- **UNVERIFIED: literature addendum claims are explicitly pending verification** (`docs/iqp-lit-scoping.md:106-115`). The epistemic null is no new project evidence: the bullets themselves say they are at abstract-level confidence pending a full read. In particular, the Oh and Oszmaniec-Brod claims, the transfer of Xie et al.'s result to this circuit, and the “closest published relative” characterization of Salavrakos cannot support corrected headlines yet. The KLM citation supports a known general limit if the source is verified, but `dual_rail.py` demonstrates one instance, not “any qubit circuit.”

- **INHERITED, not independently corrected: synthesis and README** (`docs/technical-findings.md:5-12`, `README.md:27-33,122`). They repeat the trainability/hardness corrections and say the regression tests check each closed form. The tests do check the hardness null tightly for the primary data, but trainability is only an approximate ratio check and misses the n=5-6 identity-kernel counterexample. The four Julia GO results validate underlying circuit/loss implementations; they do not validate the null interpretation or turn the conditional distribution into a hardness proof.
