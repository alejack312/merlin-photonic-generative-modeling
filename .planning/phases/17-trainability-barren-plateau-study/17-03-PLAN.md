<task type="auto">
  <name>Task 1: Build the per-n target grid and bin-index mapping</name>
  <files>trainability/target_grid.py</files>
  <action>
Create `trainability/target_grid.py` with:

1. `make_target_grid(n, lo=-0.1, hi=1.1)`: builds a `2^n`-bin grid over `[lo,hi]^2` (same bounds
   v1.0's grids already use -- `generator/bin_centers.py`/`generator/natural_grid.py`) with
   `rows = 2**((n+1)//2)`, `cols = 2**(n//2)` (so `rows*cols == 2**n` EXACTLY for every n, no
   rounding -- e.g. n=3: rows=4, cols=2; n=6: rows=8, cols=8). Build `centers` as a numpy array of
   shape `(2**n, 2)` via `np.meshgrid(np.linspace(lo,hi,rows), np.linspace(lo,hi,cols),
   indexing="ij")` then `.ravel()` and `np.stack(...)`, matching `make_natural_bin_centers`'s exact
   convention but in plain numpy (no torch -- this whole subsystem is numpy-only, per Plans
   17-01/17-02's established no-torch-in-production-path rule). Bin index `idx` (0-indexed,
   row-major, `idx = row*cols + col`) corresponds to `centers[idx]`.

   Load the empirical dataset via `generator.data.load_circles_data()` (`X_train, _ = ...`,
   torch tensor, convert to numpy via `.numpy()`), and compute `p_real` via a NUMPY nearest-bin
   assignment: pairwise distance from each data point to every center (e.g.
   `scipy.spatial.distance.cdist` or a plain broadcast), `argmin` over centers, `np.bincount(...,
   minlength=2**n)`, normalize by the total count. This must be a faithful numpy re-implementation
   of `generator/data.py`'s `compute_p_real` -- same nearest-bin-center-histogram algorithm, not a
   different method (e.g. not a KDE, not a different distance metric).

   Also build `bin_index_fn(bitstring: str) -> int`: `int(bitstring, 2)` -- the bitstring's raw
   binary integer value, stated explicitly as this module's chosen (not the only possible)
   bitstring<->grid-index convention (17-RESEARCH.md Open Question 1 -- low-risk per that
   research, since gradient-variance MAGNITUDE is not expected to be sensitive to this choice,
   unlike an actual generative-training run where spatial smoothness would matter).

   Return `(centers, p_real, bin_index_fn)` -- `centers: np.ndarray (2**n, 2)`, `p_real: np.ndarray
   (2**n,)` non-negative summing to 1.0, `bin_index_fn` a plain Python callable.

2. `bitstring_dict_to_vector(d: dict[str, float], n: int, bin_index_fn) -> np.ndarray`: generic
   utility, returns a length-`2**n` numpy array with `result[bin_index_fn(x)] = v` for each `(x,
   v)` in `d.items()`, zero elsewhere. Used for BOTH actual probability distributions (from
   `photonic_iqp_distribution`/`photonic_weight2_iqp_distribution`) AND signed parameter-shift
   deltas (from Plan 17-01's `weight1_param_shift_delta`/`weight2_param_shift_delta`) -- must NOT
   assume non-negativity or sum-to-1 (deltas can be negative and do not sum to a fixed value), so
   do not silently normalize inside this function.

Document in the module docstring: (a) the deliberate choice of `int(bitstring, 2)` as the
bin-index convention and why it's low-risk to leave undecided-by-anything-else, (b) that this
generalizes (not replaces) `generator/natural_grid.py`'s v1.0 machinery, kept fully separate so no
existing v1.0 script/checkpoint is affected.
  </action>
  <verify>`./venv/Scripts/python.exe -c "from trainability.target_grid import make_target_grid; c,p,f = make_target_grid(4); print(c.shape, p.shape, p.sum(), f('0101'))"` prints `(16, 2) (16,) 1.0 5` (0101 binary = 5).</verify>
  <done>make_target_grid(n) returns a valid (centers, p_real, bin_index_fn) triple for any n, with centers.shape==(2**n,2) and p_real non-negative summing to 1.0.</done>
</task>
