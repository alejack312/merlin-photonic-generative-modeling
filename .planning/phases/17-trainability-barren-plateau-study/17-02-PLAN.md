<feature>
  <name>Exact numpy MMD^2 loss and its quadratic-form gradient</name>
  <files>trainability/mmd_exact.py, tests/test_mmd_exact.py</files>
  <behavior>
    This repo's MMD^2 (`generator/mmd.py`) is the closed-form quadratic
    `MMD^2(p,q) = p@K@p + q@K@q - 2*p@K@q` (clamped >= 0), K = Gaussian kernel matrix over shared
    bin centers, `K[a,b] = exp(-||center_a - center_b||^2 / (2*sigma^2))`. Standard quadratic-form
    calculus gives `d(MMD^2)/dq = 2*K*(q-p)`; combined with Plan 17-01's exact per-bin derivative
    `dq_x/d(theta_k)` (a full-length vector, one entry per bin), the chain rule gives:

        d(MMD^2)/d(theta_k) = 2 * (q - p) @ K @ dq_dtheta_k

    This is EXACT, not an approximation, despite MMD^2 being quartic in the circuit's amplitudes
    (17-RESEARCH.md Pattern 2 explains why: each q_x is itself an exact linear expectation value,
    so the exact per-bin derivative composed with any downstream nonlinear function of the full
    vector q via the ordinary multivariate chain rule is still exact).

    Cases (input -> expected output):
    1. **Kernel-matrix torch parity**: build `centers` as a small numpy array (e.g. 10 random 2D
       points, seeded), compute `gaussian_kernel_matrix_np(centers, sigma)` for sigma in
       `generator/mmd.py`'s own `SIGMA_GRID`, and compare element-wise (`np.allclose`, `atol=1e-6`)
       against `generator.mmd.gaussian_kernel_matrix(torch.tensor(centers), sigma)` converted to
       numpy.
    2. **MMD^2 torch parity**: for the same centers/kernel, draw several random `p`, `q`
       probability vectors (seeded, normalized to sum to 1, non-negative), compute `mmd2_np(p, q,
       K)` and compare against `generator.mmd.mmd2(torch.tensor(p), torch.tensor(q),
       torch.tensor(K))` -- must agree to `atol=1e-6`. Include the self-comparison case
       (`mmd2_np(p, p, K) == pytest.approx(0.0, abs=1e-5)`), mirroring `tests/test_mmd.py`'s own
       fundamental-property check.
    3. **Gradient exactness via a synthetic linear model**: construct a toy `q(theta) = q0 +
       theta * dq` (both `q0` and `dq` fixed random vectors, seeded, `q0` need not itself be a
       valid probability vector for this synthetic test -- only algebraic exactness is being
       checked, not physical validity), so `MMD^2(theta) = mmd2_np(p, q0 + theta*dq, K)` is an
       exactly-known quadratic function of the scalar `theta`. Verify `mmd2_grad(q0, p, K, dq)`
       (evaluated at theta=0) matches `(mmd2_np(p, q0+h*dq, K) - mmd2_np(p, q0-h*dq, K)) / (2*h)`
       for a small `h` (e.g. 1e-5) to `atol=1e-4`, AND separately verify it matches the exact
       analytic derivative of the known quadratic `mmd2_np(p, q0+theta*dq, K)` at theta=0
       (computed by expanding the quadratic form algebraically in the test) to `atol=1e-9` --
       the second check is the real exactness proof; the finite-difference check is a redundant
       sanity cross-check.
  </behavior>
  <implementation>
    `trainability/mmd_exact.py`:
    - `gaussian_kernel_matrix_np(centers: np.ndarray, sigma: float) -> np.ndarray`: pairwise
      squared Euclidean distance (e.g. `scipy.spatial.distance.cdist(centers, centers) ** 2` or a
      plain numpy broadcast -- either is fine, prefer whichever is simplest to read) then
      `np.exp(-dist_sq / (2 * sigma ** 2))`.
    - `mmd2_np(p: np.ndarray, q: np.ndarray, kernel_matrix: np.ndarray) -> float`: `p @
      kernel_matrix @ p + q @ kernel_matrix @ q - 2 * p @ kernel_matrix @ q`, clamped to
      `max(0.0, value)` (defensive guard against float rounding noise, matching
      `generator/mmd.py`'s `torch.clamp(..., min=0)`).
    - `mmd2_grad(q: np.ndarray, p: np.ndarray, kernel_matrix: np.ndarray, dq_dtheta: np.ndarray)
      -> float`: `2.0 * (q - p) @ kernel_matrix @ dq_dtheta`.
    - No torch import anywhere in this module -- pure numpy, per CONTEXT.md's "never autograd
      through a differentiable pipeline for this circuit" rule; the torch formula in
      `generator/mmd.py` is read ONLY as a reference to port from and cross-validate against in
      tests, never imported into the production sweep path (`trainability/sweep.py`, Plan 17-05).
    - Deliberately do NOT implement a Monte-Carlo MMD² estimator or an exact/MC crossover switch
      (17-RESEARCH.md Pitfall 4: this project's binding compute constraint is the photonic
      simulation itself, not the K x K kernel matrix, so the MC fallback the sibling project needs
      at K~2^16-2^20 will essentially never trigger here at K<=2^8). Note this as a deliberate,
      documented scope decision in the module docstring, not a silent omission.

    Follow RED -> GREEN -> REFACTOR: write `tests/test_mmd_exact.py` first, confirm it fails
    (ImportError), implement `trainability/mmd_exact.py`, confirm all pass, refactor only if
    there's obvious duplication. Import `generator.mmd` and `generator.bin_centers` only inside
    the test file (for the torch-parity comparison) -- never from `trainability/mmd_exact.py`
    itself.
  </implementation>
