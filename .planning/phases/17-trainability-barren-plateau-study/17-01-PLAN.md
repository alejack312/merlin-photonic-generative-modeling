  <name>Exact parameter-shift gradient of the WP(theta,0) gate family (weight-1 and weight-2)</name>
  <files>trainability/__init__.py, trainability/param_shift.py, tests/test_param_shift.py</files>
  <behavior>
    This repo's `WP(theta,0) = exp(i*theta*Z)` gate has eigenvalue gap 2 (eigenvalues +-1), so the
    correct parameter-shift rule (derived and numerically verified in 17-RESEARCH.md Pattern 1) is:

        d(prob_x)/d(theta_k) = prob_x(theta + (pi/4)*e_k) - prob_x(theta - (pi/4)*e_k)

    exact, no division, no 1/2 factor -- NOT the textbook `shift=pi/2, divide by 2` rule (that rule
    is for the different convention `exp(-i*theta*Z/2)`; applied here it lands on `sin(2*pi/2)=0`
    and silently produces an all-zero "gradient" for every theta).

    This holds for every weight-1 `thetas[k]` in `photonic_iqp_distribution(n, thetas)`, and for
    the SAME `thetas[k]` parameters in `photonic_weight2_iqp_distribution(n, i, j, thetas)` --
    the pi/4 fold that function applies internally to `thetas[i]`/`thetas[j]` (realizing the
    Z_i*Z_j interaction) is an ADDITIVE CONSTANT on top of `thetas[k]`, which shifts the phase
    offset but not the frequency, so the same shift=pi/4 rule remains exact (17-RESEARCH.md
    Pattern 1, final paragraph).

    Cases (input -> expected output), all to be encoded as pytest tests:
    1. **Weight-1, closed-form exactness** (n in {1,2,3}, >=5 random theta draws each, seeded):
       `weight1_param_shift_delta(n, thetas, k)` must equal the exact analytic derivative of
       `expected_joint_distribution(n, thetas)` with respect to `thetas[k]`, computed as:
       for each bitstring `bits`, `d(dist[bits])/d(thetas[k])` = (product of every OTHER qubit's
       marginal factor) * (`-sin(2*thetas[k])` if `bits[k]=='H'` else `+sin(2*thetas[k])`)
       (since `expected_single_qubit_probs` gives `P(H)=cos^2(theta)`, `P(V)=sin^2(theta)`, and
       `d/d(theta) cos^2(theta) = -sin(2*theta)`, `d/d(theta) sin^2(theta) = +sin(2*theta)`).
       Assert agreement to `atol=1e-9` for every bitstring, every draw.
       NOTE: `photonic_iqp_distribution` uses '0'/'1' bitstrings (0='H', 1='V' per
       `fock_to_bitstring`) -- build the analytic reference directly in that alphabet, don't
       round-trip through `expected_joint_distribution`'s 'H'/'V' alphabet without translating.
    2. **Weight-2, finite-difference cross-check** (n in {2,3}, (i,j)=(0,1), >=3 random theta
       draws, seeded): `weight2_param_shift_delta(n, 0, 1, thetas, k)` for each `k` must agree
       with a central finite-difference of `photonic_weight2_iqp_distribution` at a small step
       (e.g. `eps=1e-4`: `(dist(theta+eps*e_k) - dist(theta-eps*e_k)) / (2*eps)`, using the SAME
       union-of-keys-with-0-default convention) to within `atol=1e-4` (finite-difference has
       O(eps^2) truncation error at this eps -- do not use a tighter atol than the method
       supports). This is an independent numerical check, not a repeat of Pattern 1's exact
       algebra, since weight-2's distribution has no simple closed form to hand.
    3. **Pi/2-shift pitfall regression** (n=1, weight-1, several theta values, e.g. 0.3, pi/6,
       pi/3): compute `photonic_iqp_distribution(n, [theta+pi/2]) - photonic_iqp_distribution(n,
       [theta-pi/2])` directly (bypassing `weight1_param_shift_delta`, which must never take
       `pi/2` as a parameter) and assert every resulting delta is within `atol=1e-9` of exactly
       0.0 -- confirming the failure mode 17-RESEARCH.md's Pitfall 1 describes is real and would
       be silent (not a crash) if someone used the wrong shift value.
  </behavior>

    `trainability/param_shift.py`:
    - Module constant `SHIFT = np.pi / 4`.
    - `weight1_param_shift_delta(n, thetas, k) -> tuple[dict[str, float], float]`: builds
      `thetas_plus`/`thetas_minus` (copies of `thetas` as a plain list -- never mutate the
      caller's list, matching this repo's established convention in `iqp_photonic_encoding.py`),
      calls `photonic_iqp_distribution(n, thetas_plus)` and `..._minus`, returns
      `({x: dist_plus.get(x,0.0) - dist_minus.get(x,0.0) for x in union_of_keys}, max(residual_plus,
      residual_minus))` -- the second element is a diagnostic residual bound (should be ~0 for
      this repo's ideal weight-1 circuit, per its own docstring; do not assert on it inside the
      library function, just surface it for the caller to check).
    - `weight2_param_shift_delta(n, i, j, thetas, k) -> tuple[dict[str, float], float, float]`:
      same pattern around `photonic_weight2_iqp_distribution(n, i, j, thetas_plus/minus)`, which
      returns a 3-tuple `(dist, residual, herald_failure_prob)` -- surface `max(residual_plus,
      residual_minus)` and `max(herald_fail_plus, herald_fail_minus)` as two diagnostics.
