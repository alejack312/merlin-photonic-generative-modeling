**`trainability/rng.py`**: implement a deterministic, reorder-safe seed-derivation utility (this
repo has no existing convention of its own for this -- 17-RESEARCH.md's Don't-Hand-Roll table
explicitly recommends mirroring the sibling project's `derive_seed`/`split_rng` shape, not its
code verbatim). Minimal API:

```python
import hashlib
import numpy as np

def derive_seed(*parts) -> int:
    """Stable integer seed from arbitrary labeled parts (e.g. (n, generator_scope, init_scheme,
    draw_index)) -- adding/reordering a setting elsewhere never shifts another setting's seed,
    since each seed is a pure hash of its OWN full coordinate tuple, not a running counter."""
    payload = repr(tuple(parts)).encode("utf-8")
    digest = hashlib.blake2b(payload, digest_size=8).digest()
    return int.from_bytes(digest, "big") % (2**31 - 1)

def get_rng(*parts) -> np.random.Generator:
    return np.random.default_rng(derive_seed(*parts))
```

**`trainability/stats.py`**: `summarize_gradient_samples(grads: np.ndarray) -> dict` returning at
minimum `{"n_samples": len(grads), "mean": ..., "var": ..., "std": ..., "median": ...,
"abs_mean": ..., "rms": ...}` (root-mean-square, `sqrt(mean(grads**2))` -- useful since raw
gradient means can be near-zero by symmetry while variance/rms is the barren-plateau-relevant
quantity). All values plain Python floats (`float(...)`), not numpy scalars, for clean CSV/JSON
serialization downstream. Keep this module self-contained (pure numpy, no dependency on the
sibling project's code) -- the STATISTICS being computed are standard and domain-agnostic (mean,
variance, RMS), so there is no meaningful "port" to do here beyond matching the sibling's general
shape of "report several angles on the same sample," not its implementation.
