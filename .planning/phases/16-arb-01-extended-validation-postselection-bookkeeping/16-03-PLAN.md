2. The property to check: for every valid `(n, i, j)` with `0 ≤ i, j < n`, `i ≠ j`, the 8 values on the RIGHT side don't matter (they're a fixed local target, 0-7) — what must be checked is that the 8 KEYS `{2i, 2i+1, 2j, 2j+1, 2n, 2n+1, 2n+2, 2n+3}` are pairwise distinct (injective as a function domain) — collisions checked against ALL n qubits' own data ports (`0..2n-1`), not just qubit i/j's, per `16-CONTEXT.md`'s explicit instruction to model the fully general property even though it's provably impossible by construction (ancilla ports start at `2n ≥` the max qubit port `2n-1`).
3. Forge basics needed: this is a **relational** (not temporal) model — a static structural property, no state transitions. `pred` blocks define properties over `Int` sigs; arithmetic needs explicit functions (`add`, `multiply`, NOT `+`, which is set union for Forge's `Int`); comparisons (`<`, `<=`, `>`, `>=`, `=`, `!=`) work directly; `test expect { name: {...} for N Int is sat/unsat }` runs a check (bare `expect` without `test` is a silent no-op); `option run_sterling off` is required as the file's second line to avoid a Windows hang when Forge tries to launch its visualizer.
4. The two-part pass criteria (per `16-CONTEXT.md`): (a) a `sat` check confirming at least one valid `(n,i,j)` instance exists at all (guards against a vacuously-true, over-constrained model — the classic Forge pitfall), and (b) an `unsat` check confirming no `(n,i,j)` counterexample to the injectivity property exists within the chosen bound.

Using Task 1's recorded attempt as the basis (check it against the model below; correct if needed, showing the correction rather than silently replacing it), create the `forge/` directory and write `forge/ancilla_mapping.frg`. A verified-working version of this exact model was built and executed live during this phase's research (16-RESEARCH.md) — use it as the confirmed scaffold, adjusting only the header comment and the n-bound to n≤8 (the top of `16-CONTEXT.md`'s allowed [6,8] range — research confirmed this solves in ~1.2s total, so there's no performance reason to pick a smaller bound):

```racket
#lang forge
option run_sterling off

-- Structural correctness check of the CP(alpha) insertion's local->global
-- ancilla mode-index mapping dict (iqp_photonic_encoding.py,
-- _build_weight2_cp_processor_no_postselect, lines 622-627):
--   mapping = {2i:0, 2i+1:1, 2j:2, 2j+1:3, 2n:4, 2n+1:5, 2n+2:6, 2n+3:7}
-- ARB-09 (Phase 16): confirms the mapping's 8 KEYS are pairwise distinct
-- (injective) for every valid (n,i,j), checked against ALL n qubits' own
-- data ports (0..2n-1), not just qubit i/j's -- the fully general property
-- (16-CONTEXT.md's explicit instruction), even though it is provably
-- impossible to collide by construction (ancilla ports start at 2n, which
-- is >= the max qubit port 2n-1).

pred validTriple[n, i, j: Int] {
    n >= 2
    n <= 8
    i >= 0
    i < n
    j >= 0
    j < n
    i != j
}

pred distinctPorts[n, i, j: Int] {
    let pi0 = multiply[2, i], pi1 = add[multiply[2, i], 1],
        pj0 = multiply[2, j], pj1 = add[multiply[2, j], 1],
        a0 = multiply[2, n], a1 = add[multiply[2, n], 1],
        a2 = add[multiply[2, n], 2], a3 = add[multiply[2, n], 3] | {
        pi0 != pi1  pi0 != pj0  pi0 != pj1  pi0 != a0  pi0 != a1  pi0 != a2  pi0 != a3
        pi1 != pj0  pi1 != pj1  pi1 != a0  pi1 != a1  pi1 != a2  pi1 != a3
        pj0 != pj1  pj0 != a0  pj0 != a1  pj0 != a2  pj0 != a3
        pj1 != a0  pj1 != a1  pj1 != a2  pj1 != a3
        a0 != a1  a0 != a2  a0 != a3  a1 != a2  a1 != a3  a2 != a3
        -- ancilla ports must not collide with ANY qubit's own data port
        -- (0..2n-1), not just qubit i/j's -- the fully general property.
        all k: Int | (k >= 0 and k < multiply[2, n]) implies {
            k != a0
            k != a1
            k != a2
            k != a3
        }
    }
}

test expect {
    -- Part 1: non-vacuity -- guards against a vacuously-true,
    -- over-constrained model (the classic Forge pitfall).
    nonVacuous: {
        some n, i, j: Int | validTriple[n, i, j]
    } for 6 Int is sat

    -- Part 2: no counterexample to injectivity/non-collision within bound.
    noCounterexample: {
        some n, i, j: Int | validTriple[n, i, j] and not distinctPorts[n, i, j]
    } for 6 Int is unsat
}
```

Note: `for 6 Int` sets the bitwidth (range [-32,31]), not the n-bound itself -- n≤8 is enforced inside `validTriple`. Bitwidth 6 was confirmed sufficient in research (the largest value the model touches is `2*8+3=19`, well under 31).

Run via `racket forge/ancilla_mapping.frg` (NOT `raco forge` -- that subcommand does not exist in Forge v5.2, confirmed in 16-RESEARCH.md Pitfall 2). Confirm both `nonVacuous` and `noCounterexample` print `Test passed:` with exit code 0.
