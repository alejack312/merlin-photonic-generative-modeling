<objective>
Implement `build_cz_insertion(n, i, j)` -- the `PBS`-wrap -> `heralded_cz` -> `PBS`-unwrap sub-circuit that lets two qubits' polarization-encoded ports interact via the catalog's heralded CZ gate -- and prove, via an executable truth table (computational basis AND coherent superposition inputs), that it reproduces `diag(1,1,1,-1)` exactly on this module's own bit convention.

Purpose: This is the phase's foundational primitive (ROADMAP Phase 11, Success Criterion 1) and its riskiest piece of novel mechanics -- 11-RESEARCH.md found, by direct execution against this repo's venv, that `heralded_cz`'s internal ctrl/data bit convention is inverted relative to this module's own PBS-derived dual-rail convention (Pitfall 1). Left unfixed, the CZ's `-1` phase lands on `|00>` instead of `|11>` -- a "physically wrong but self-consistent" bug of exactly the same shape as Plan 09-02's H/V port-labeling fix, which no test caught until a direct calibration check was added. This plan is the direct check for weight-2.

Design decision (locked, not left to the executor to re-derive): the swap fix lives INSIDE `build_cz_insertion`'s own wiring (an internal `PERM([1,0])` on each qubit's dual-rail pair, immediately before and after the `heralded_cz` sub-block), not in the caller's mode-mapping dict. This keeps `build_cz_insertion`'s external contract simple and matches the "reusing weight-1 builders unmodified" spirit the whole module already follows: give it qubit i/j's ports in the module's normal order, get back a correctly-signed CZ. A bug in this fix is then visible in one function, not smeared across every call site.

This is a self-explanation checkpoint candidate per this repo's CLAUDE.md (novel mechanics: herald/mode-offset wiring, the dual-rail swap correction) -- Task 1's action below is written with enough inline reasoning that the owner can follow and later explain it unaided, matching this module's existing documentation density (see the API-facts comment block at the top of iqp_photonic_encoding.py and heralded_cz_derisking.py's module docstring).

Output: `build_cz_insertion(n, i, j)` in `iqp_photonic_encoding.py`, verified by an executable truth table in `tests/test_iqp_photonic_encoding.py`.

2. Implement `build_cz_insertion(n, i, j)`. It builds a **local, self-contained `Circuit(6)`** (not sized to the outer 2n-mode register -- the caller wires it in via a mode-mapping dict in Plan 11-02) with this local layout, matching `heralded_cz`'s own numbering:
   - local 0 = qubit i's polarization-carrying port (module's normal convention)
   - local 1 = qubit i's vacuum-partner port
   - local 2 = qubit j's polarization-carrying port
   - local 3 = qubit j's vacuum-partner port
   - local 4, 5 = herald ancilla (owned entirely by `heralded_cz`, never touched by the caller except for herald re-registration)

   Wiring, in order (write out each step as a separate `circuit.add(...)` call, matching this module's existing explicit-loop style rather than a clever one-liner, so the structure stays legible):
   ```
   circuit = pcvl.Circuit(6)
   circuit.add(0, pcvl.PBS())        # wrap qubit i: polarization -> dual rail, local (0,1)
   circuit.add(2, pcvl.PBS())        # wrap qubit j: polarization -> dual rail, local (2,3)
   circuit.add(0, pcvl.PERM([1, 0])) # ctrl/data swap fix (11-RESEARCH.md Pitfall 1): heralded_cz's
                                      # internal bit convention is inverted relative to this module's
                                      # PBS-derived dual rail -- without this, the CZ's -1 phase lands
                                      # on |00> instead of |11>. Verified by direct execution (see
                                      # 11-RESEARCH.md "Pitfall 1"). Swapping qubit i's dual-rail pair
                                      # order right before heralded_cz corrects this.
   circuit.add(2, pcvl.PERM([1, 0])) # same swap for qubit j's pair
   item = HeraldedCzItem()
   circuit.add(0, item.build_circuit())  # bare 6-mode heralded_cz: ctrl=local(0,1), data=local(2,3), herald=local(4,5)
   circuit.add(0, pcvl.PERM([1, 0])) # swap back: undo the ctrl-side relabeling so this function's own
                                      # local port 0 is still "qubit i's polarization port" for the caller
   circuit.add(2, pcvl.PERM([1, 0])) # swap back for qubit j
   circuit.add(0, pcvl.PBS())        # unwrap qubit i: dual rail -> polarization, local (0,1)
   circuit.add(2, pcvl.PBS())        # unwrap qubit j: dual rail -> polarization, local (2,3)
   ```
   Note: `n`, `i`, `j` are accepted for interface symmetry with the other `build_*` functions and for a future caller to validate `0 <= i < j < n`, but the circuit body itself is always a fixed local `Circuit(6)` -- add an `assert 0 <= i < n and 0 <= j < n and i != j` at the top.

3. Herald spec: read `herald_spec = HeraldedCzItem().build_experiment().in_heralds` (NOT hardcoded -- same pattern `heralded_cz_derisking.py`'s `measure_cz_phase` already uses). This will be `{4: 1, 5: 1}` (local indices into this function's own `Circuit(6)`, which line up exactly with `heralded_cz`'s own numbering since its bare circuit is added at local offset 0).

4. Return `(circuit, herald_spec)` -- a 2-tuple, per the CONTEXT.md decision ("the function also surfaces the herald mode offsets/spec... as a second return value").

Write a docstring on `build_cz_insertion` that states, in the module's existing voice: what the function does, the local 6-mode layout, the swap-fix rationale (one sentence, pointing to 11-RESEARCH.md's Pitfall 1 the way other docstrings in this file point to Plan 09-02's fix), and that `herald_spec` is read from `in_heralds`, not hardcoded.
