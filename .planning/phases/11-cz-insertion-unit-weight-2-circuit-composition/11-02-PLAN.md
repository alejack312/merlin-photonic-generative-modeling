<objective>
Compose the full weight-2 generator pipeline: `Processor(2n+2)` assembled from `build_state_prep_circuit`, a `pi/4`-folded `build_diagonal_layer_circuit`, Plan 11-01's `build_cz_insertion` (wired in via a mode-mapping dict with immediate herald re-registration), `build_conjugation_circuit`, and `build_readout_circuit` -- every weight-1 builder reused completely unmodified, per WT2-01's explicit requirement.

Purpose: This is the phase's remaining 3 success criteria (ROADMAP Phase 11, criteria 2-4) -- turning the verified `build_cz_insertion` primitive from Plan 11-01 into an actual runnable weight-2 circuit, wired the way 11-RESEARCH.md's architecture section specifies (`Processor("SLOS", 2*n+2)`, weight-1 builders added at `.add(0, ...)` unchanged, `build_cz_insertion` added via a dict mapping, `add_herald` called immediately after -- never relying on `_compose_experiment`'s auto-shift, per the CONTEXT.md decision that herald re-registration must be explicit and auditable).

Design decisions this plan implements (locked, not re-derived at execution time):
- **Theta folding is additive**: `thetas_folded[k] = thetas_base[k] + pi/4` for `k in {i, j}` only, all other qubits' thetas pass through unchanged. This is what makes Phase 13's later weight-1+weight-2 mixed-circuit test well-defined -- deciding this now avoids retrofitting the composition logic later.
- **Herald registration is explicit and immediate**: call `add_herald` right after the `Processor.add()` call that wires in `build_cz_insertion`'s output, using the `herald_spec` Plan 11-01 already made available (never hardcoded indices) -- this is the concrete guard Success Criterion 3 exists to enforce (`Processor.heralds` reads `{}` until `add_herald` is called explicitly; forgetting it silently produces an unheralded raw unitary that still "runs" without error).
- **Non-regression beyond the existing suite**: because this phase touches a module every prior phase also depends on, add a lightweight snapshot check confirming weight-1 builder output is bit-identical to before this phase's changes -- the same category of risk (unmodified module edited by a phase whose real focus is elsewhere) that produced Phase 9's silent H/V labeling bug.

This is a self-explanation checkpoint candidate per this repo's CLAUDE.md (novel mechanics: mode-offset wiring across a dict mapping, herald re-registration at shifted global indices) -- Task 1's action is written with the reasoning inline so the owner can follow and later explain the composition unaided.

Output: `build_weight2_processor(n, i, j, thetas)` in `iqp_photonic_encoding.py`, verified by herald/sanity/regression tests in `tests/test_iqp_photonic_encoding.py`, full existing suite green.

1. `assert len(thetas) == n` and `assert 0 <= i < n and 0 <= j < n and i != j` (same validation style as `build_diagonal_layer_circuit`).

2. Fold the `pi/4` corrections additively -- copy `thetas` (never mutate the caller's list), increment index `i` and index `j` by `np.pi / 4` each:
   ```
   thetas_folded = list(thetas)
   thetas_folded[i] += np.pi / 4
   thetas_folded[j] += np.pi / 4
   ```
   Comment inline: this realizes the CZ/ZZ operator identity already documented in `docs/iqp-photonic-encoding.md` (`exp(i*pi/4*Z_i*Z_j) = CZ . exp(i*pi/4*Z_i) . exp(i*pi/4*Z_j)` up to global phase) -- the single-qubit corrections fold additively into the SAME `thetas` argument any weight-1 generator on qubits i/j would already be using, per the CONTEXT.md-locked folding rule (base angle + pi/4, not a replacement) that Phase 13's mixed-circuit test will depend on.

3. Build the outer processor with room for the 2 herald ancilla modes from construction (11-RESEARCH.md Pitfall 2 -- `Processor.add()` requires every mapping target mode to already exist):
   ```
   total_modes = 2 * n + 2
   proc = pcvl.Processor("SLOS", total_modes)
   ```

4. Add the weight-1 builders unchanged, exactly as `build_full_circuit` already does, at `.add(0, ...)`:
   ```
   proc.add(0, build_state_prep_circuit(n))
   proc.add(0, build_diagonal_layer_circuit(n, thetas_folded))
   ```

5. Wire in Plan 11-01's `build_cz_insertion` via an explicit, straight (unswapped -- the swap fix already lives inside `build_cz_insertion` itself) mode-mapping dict:
   ```
   cz_circuit, herald_spec = build_cz_insertion(n, i, j)
   mapping = {
       2 * i: 0, 2 * i + 1: 1,      # qubit i's ports -> build_cz_insertion's local (0,1)
       2 * j: 2, 2 * j + 1: 3,      # qubit j's ports -> build_cz_insertion's local (2,3)
       2 * n: 4, 2 * n + 1: 5,      # tail ancilla modes -> build_cz_insertion's local herald ports
   }
   proc.add(mapping, cz_circuit)
   ```
   Comment inline, citing 11-RESEARCH.md: `Processor.add`'s `ModeConnector` auto-inserts a `PERM` before this component and its exact inverse after, so the outer processor's mode numbering (`2i` is still "mode `2i`") is transparently restored for every `.add()` call that follows -- verified by direct execution in 11-RESEARCH.md, not assumed.

6. Register the heralds IMMEDIATELY after that `.add()` call, using `herald_spec` (never hardcoded `4`/`5` -- those are `build_cz_insertion`'s LOCAL indices, which the mapping dict above sends to global `2*n`/`2*n+1`):
   ```
   proc.add_herald(2 * n, herald_spec[4])
   proc.add_herald(2 * n + 1, herald_spec[5])
   ```
   Comment inline: this is the exact guard Success Criterion 3 exists for -- composing a bare `Circuit` (as opposed to an `Experiment`/`Processor`) never auto-propagates herald metadata (`Experiment._add_component`'s plain-component path has no herald logic, unlike `_compose_experiment`); forgetting this call silently produces a processor that runs an un-heralded raw unitary with no error.

7. Add the remaining weight-1 builders unchanged:

   ```
   proc.add(0, build_readout_circuit(n))
   return proc
   ```
