Create `pooled_allocation_baseline.py` at the repo root. Python standard library only — `itertools` and `time` suffice, no new packages. Do not place it under `tests/` and do not import it from anything in `tests/`; this phase stays outside `pytest` per Phase 16's precedent, and `pytest.ini`'s `testpaths = tests` must remain unaffected.

Implement four things:

1. `edges(n)` — the `C(n,2)` pairs `(i, j)` with `0 <= i < j < n`, and `conflicts(p, q)` returning True when `{p} ∩ {q}` is non-empty. These must mirror `pairsAreKn` and `conflicts` in the Forge model exactly; a mismatch here silently invalidates the whole comparison, so state the correspondence in a comment naming the Forge predicate each mirrors.

2. `greedy_colouring(n, order=None)` — first-fit greedy: walk the edges in the given order, assign each the lowest block index not used by any conflicting already-coloured edge. Return the colouring and the number of blocks used. Note in a comment that greedy is an upper bound, not a minimum — it is the fast half of the baseline, and on its own it cannot answer the minimality question Forge does.

3. `backtracking_min_colouring(n, k_start=None)` — the actual SEARCH, and the fair comparison against Forge. For descending `K`, attempt to construct a proper colouring by depth-first assignment with backtracking; return the smallest `K` for which one exists, plus a witness colouring, plus the `K+1` value at which the search proved infeasibility. This is the direct analogue of Forge's `colouringExists` / `minimality` pair — it must both FIND a colouring and establish that `K-1` is impossible, or it is not a fair baseline. Apply a per-`n` wall-time ceiling of 10 minutes matching D-04; if it is hit, record the timeout as the result for that `n` rather than reducing the problem.

4. `round_robin_colour(n, i, j)` — a direct reimplementation of the closed-form formula from `results/phase22_allocation_invariant.md`: for odd `n`, `(i + j) % n` using `K = n` blocks; for even `n`, with `m = n - 1`, `(i + j) % m` when both `i, j < m` and `(2 * i) % m` when `j == n - 1`, using `K = n - 1` blocks. Then `check_round_robin(n)` — verify independently that this formula (a) is a proper colouring under `conflicts`, and (b) uses exactly the claimed block count. This is the link between the prose specification and the search result: Forge finds the minimum `K` abstractly, and this check confirms the concrete formula an eventual implementation would use actually achieves it.

Add a secondary, explicitly-labelled data point per `22-RESEARCH.md` Research Question 5: `naive_subset_scan(n, time_budget_s)` — enumerate subsets of the edge set and check the invariant per subset, purely to measure what the original `2^28`-subset framing would have cost. Time-box it to the same 10-minute ceiling and report how far it got (e.g. "reached `n=5` in Xs; at `n=8` covered N of 2^28 subsets before the ceiling"). Label it in output as a SECONDARY data point, not the primary comparison — the primary model is pairwise-reduced and does not check subsets, so presenting subset-scan time as the baseline would inflate Forge's apparent advantage.

Provide an argparse CLI with `--n-max` (default 8), `--time-ceiling` (default 600 seconds) and `--skip-naive`. Print a per-`n` table: `n`, `C(n,2)`, `greedy_K`, `min_K` (from backtracking), `infeasible_at`, `round_robin_K`, `round_robin_proper` (True/False), `greedy_seconds`, `backtracking_seconds`. Run it from `n=2` through `n=8`, and continue past 8 if it stays fast — extending past Forge's bound is itself informative, exactly as ARB-09's audit brute-forced to `n=2000`.

If `min_K` from backtracking disagrees with Forge's minimum at any `n`, do NOT adjust either side to agree. Record the disagreement, state which `n`, and flag it as a real finding requiring investigation — one of the two encodings is wrong, and that is the most valuable thing this task could surface.
